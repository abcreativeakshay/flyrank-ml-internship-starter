# The Plan to Keep Building

A portfolio dies when it stops at launch. This is the short plan for how mine keeps growing.

## How to add the next case (the repeatable steps)

1. **Pick work that is finished and measured.** A case needs a result, not an intention — a live link, a score, a shipped artifact. If it isn't done, it isn't a case yet.
2. **Write it in the case frame:** problem → what I built → evidence/numbers → what it proves. Plain words, numbers over adjectives, leakage and limitations stated honestly.
3. **Add it to the site:** one new block in the Cases section of the page, ordered by strength of evidence, plus a line in the sitemap if it gets its own page.
4. **Pressure-test it** with the same prompt style I used on the sitemap — make the AI argue that the case is weak, fix what survives the argument.
5. **Push and check:** `git push`, open the live page on a phone, confirm it renders and the numbers match the source.
6. **Log the gap it leaves** in the "still need to gather" list (a video, a testimonial, a screenshot) so the next improvement is already named.

## The named next piece

**A written case study page for the FlyRank ML capstone** — the full story behind the one-line result: the lane choice, the data contract, why the trend columns are leakage, the baseline-to-model climb from Precision@50 0.24 → 0.48 → 0.68, and what the validation audit caught. It is my strongest measured work, and right now it only exists as a paragraph; it deserves the page.

## The reminder

A weekly reminder is set to work on it — one sitting a week on the next piece, starting with the FlyRank capstone case study page, so the portfolio keeps moving instead of waiting for a free day that never comes.
